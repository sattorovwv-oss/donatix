# Android FCM — обновление v7

Использовать отдельное дополнение Android_Server_Addon, а не старый server_patch.
Дополнение не заменяет исходники сайта и хранит мобильные устройства в отдельной
базе. Порядок проверки, установки и отката: Android_Server_Addon/README_RU.md.
На рабочий сервер оно пока не установлено.

1. Firebase-проект клиента и сервера должен совпадать. Текущая настройка:
   donatix-660fc, Android package tj.donatix.app.
2. В Codemagic группа donatix_android содержит Secret-переменную
   GOOGLE_SERVICES_JSON с полным Android google-services.json. Она остаётся
   в Codemagic; архив не включает личный файл владельца.
3. На сервере нужен отдельный service-account JSON с правом отправки FCM.
   Это закрытый ключ, а не Android google-services.json. Хранить его только
   на сервере в закрытом файле, доступном пользователю donatix:
   /etc/donatix/firebase-service-account.json. Не отправлять ключ в чат или GitHub.
4. Подготовленный systemd drop-in задаёт путь к ключу, Firebase project и
   отдельной мобильной базе. Сначала проверить совместимость через stage.py,
   сделать согласованную резервную копию и проверить откат. Старые файлы сайта,
   .env, nginx, цены и обработчики заказов не заменяются.
5. После установки /api/v1/android/config должен вернуть fcm_enabled: true.
   Некорректный или отсутствующий ключ выключает FCM, сохраняя работу сайта.
6. Собрать подписанный release APK/AAB версии 7. На Android включить уведомления
   в приложении и разрешить их системе. Проверить реальное событие заказа,
   фон, холодный запуск, повтор, выход и переход в другой аккаунт.

Дополнение читает новые события notifications примерно раз в секунду,
отправляет data-only FCM с привязкой к сессии и повторяет временные ошибки.
Резервная проверка использует те же ID и не отмечает сообщения сайта прочитанными.
Сеть, Firebase и ограничения Android могут задерживать доставку.

Google OAuth на сайте настраивается отдельно. Вход приложения v7 использует
существующий браузерный Google-вход с одноразовой передачей сессии; новых
redirect URI для описанного варианта не требуется. iOS в этом обновлении не меняется.

Проверки кода не подтверждают реальную доставку: владелец должен настроить свой
ключ, дополнение должно быть установлено, а уведомление проверено на телефоне.
