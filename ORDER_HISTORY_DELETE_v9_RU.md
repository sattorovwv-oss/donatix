# Donatix: история заказов и удаление аккаунта — v9

Обновление подготовлено для текущего Android-проекта из GitHub (исходная версия `03b6280`). Оно меняет историю заказов, удаление аккаунта и очистку данных на Android. В серверное дополнение добавлены соответствующие маршруты и обработчик удаления. Для применения нужны **обновление дополнения на сервере и новая release-сборка приложения**.

## Что исправлено

История больше не зависит от точного текста строки статистики в HTML сайта. Клиент получает JSON через `/api/v1/android/orders` с существующими фильтрами сайта: статус, поиск, даты, часовой пояс и страницы по 30 заказов. Чужие заказы недоступны. На старой версии дополнения сохраняется чтение корректных карточек HTML; ошибка авторизации или сервера не превращается в пустую историю.

Удаление доступно в приложении через «Ещё» → «Удаление аккаунта». Нужны подтверждение `УДАЛИТЬ` и текущий пароль либо повторный вход в течение последних 5 минут, в том числе через Google. Доступ, сессии, API-ключи и боты отключаются сразу. Очистка выполняется в фоне: обработчик сначала даёт уже принятым запросам завершиться. При обычном аккаунте с нулевым балансом очистка начинается примерно через минуту; файлы ботов могут потребовать дополнительного времени.

При остатке баланса, заказах в обработке или пополнениях на проверке заявка сохраняется. Существующие расчёты завершаются обычным способом. Для возврата остатка клиент обращается в поддержку; оператор проводит расчёт через действующую административную панель. Обработчик продолжает удаление после завершения операций и обнуления баланса. Автоматическое списание или выдуманный возврат денег не выполняется. Администратору сначала нужно передать управление.

Очищаются профиль, контакты, Google/Telegram-привязки, пароли, сессии, ключи, токены ботов, переписка поддержки, сохранённые ID игроков, содержание уведомлений и файлы чеков. На телефоне очищаются учётные данные, временные копии чеков, фотографий и загрузок, а также уведомления. Исходные фотографии в галерее телефона принадлежат пользователю.

Для учёта и защиты от повторного зачисления сохраняются суммы и статусы завершённых операций, платёжные идентификаторы и отпечатки чеков без профиля, ID игроков и содержимого чеков. Технические номера аккаунта, ботов и пустых уведомлений резервируются: их повторное использование могло бы смешать клиентов или нарушить доставку push. Это объясняется перед подтверждением удаления. Имена удаляемого клиента в связанных реферальных бонусах убираются, суммы бонусов сохраняются.

## 1. Обновить проект и GitHub на Windows

Скачайте `Donatix_Orders_Deletion_v9.zip`. В обычном PowerShell выполните блок целиком:

```powershell
& {
    $ErrorActionPreference = "Stop"
    $zip = Get-ChildItem "$env:USERPROFILE\Downloads", "$env:USERPROFILE\Desktop" `
        -Filter "Donatix_Orders_Deletion_v9*.zip" -File |
        Sort-Object LastWriteTime -Descending | Select-Object -First 1
    if (-not $zip) { throw "Сначала скачай архив в Загрузки или на рабочий стол." }
    $update = "$env:USERPROFILE\Desktop\Donatix_Orders_Deletion_v9"
    Expand-Archive -LiteralPath $zip.FullName -DestinationPath $update -Force
    powershell -NoProfile -ExecutionPolicy Bypass -File "$update\Apply_Android_Update_v9.ps1" -Push
    if ($LASTEXITCODE -ne 0) { throw "Обновление остановилось. Сохрани полный текст ошибки." }
}
```

Скрипт проверяет исходные файлы перед заменой и учитывает Windows CRLF. Он сохраняет ранее исправленный вариант Google-входа, если он находится в вашей папке. В GitHub отправляются только файлы этого обновления. Используется существующая папка `Donatix_Android_iOS_v4`; `.git`, подпись и настройки Codemagic сохраняются. Если у папки другое расположение, укажите его параметром `-Repo "полный путь"`.

## 2. Установить только обновление дополнения на сервере

Серверный архив внутри скачанного обновления содержит установщик, проверочный манифест и три модуля дополнения. Установщик сохраняет текущую реализацию Google-входа, меняя только участки подключения двух новых функций. Исходники сайта, `.env`, nginx, конфигурация systemd и схема основной базы не переписываются. Установка выполняет **один перезапуск сервиса `donatix`**, поэтому выберите спокойное время.

На Windows после предыдущего шага выполните:

```powershell
$update = "$env:USERPROFILE\Desktop\Donatix_Orders_Deletion_v9"
scp "$update\Donatix_Orders_Server_v9.zip" root@2.29.11.118:/root/Donatix_Orders_Server_v9.zip
```

После успешной загрузки подключитесь:

```powershell
ssh root@2.29.11.118
```

В терминале сервера (`root@uways`) выполните:

```bash
python3 -m zipfile -e /root/Donatix_Orders_Server_v9.zip /root/Donatix_Orders_Server_v9
python3 /root/Donatix_Orders_Server_v9/update_orders_deletion.py
python3 /root/Donatix_Orders_Server_v9/update_orders_deletion.py --apply
```

Сначала проходит проверка текущего кода, схемы и сервиса. Если она завершилась с `STOP`, следующие команды установки не выполняйте: сохраните текст ошибки. Установщик также повторяет проверку перед применением. Успешная установка заканчивается:

```text
Order history and account deletion activated: OK
Existing site, API, Google and FCM health checks: OK
```

При ошибке запуска установщик восстанавливает предыдущий код дополнения. База не откатывается: новые операции клиентов сохраняются. Путь резервной копии кода выводится в конце. Ручной откат кода при необходимости:

```bash
python3 /root/Donatix_Orders_Server_v9/update_orders_deletion.py --rollback /var/backups/donatix-android/ПУТЬ_ИЗ_ВЫВОДА
```

Откат кода не восстанавливает удалённые аккаунты. Для ожидающих заявок нужно снова включить эту версию обработчика, чтобы автоматическая очистка продолжилась.

## 3. Получить новый APK/AAB

В Codemagic выберите ветку `main` и существующий workflow **`android-release` — Donatix signed Android APK and Play AAB**. Используются ваши уже настроенные ключи подписи и Firebase. Установите новый release APK поверх текущего, затем проверьте историю под своим аккаунтом: все заказы, поиск, статусы, даты и следующую страницу. Один рабочий заказ удобно сравнить с сайтом.

Для проверки удаления используйте отдельный созданный для этого аккаунт с нулевым балансом. Подтвердите удаление, убедитесь, что приложение вышло из аккаунта и прежний аккаунт после фоновой очистки недоступен. Повторная регистрация, в том числе через Google, может создать новый пустой аккаунт; старые данные и баланс в него не возвращаются. Остаток средств проверяйте на отдельном аккаунте: заявка должна ожидать расчёта, а деньги — сохраняться. Настоящий оплаченный клиентский аккаунт для такой проверки не нужен.

После установки будет доступна внешняя страница удаления для Google Play:

`https://donatix.tj/android/account-deletion`

Она позволяет запросить удаление через вход на сайте без установленного приложения. В политике конфиденциальности и Play Console необходимо отразить фактическое сохранение расчётных записей и отпечатков платежей. Владелец отдельно устанавливает сроки хранения журналов, резервных копий и уже отправленных сообщений сторонних сервисов; этот установщик не управляет внешними копиями.

## Проверка изменений

Проверены Flutter-анализ, 85 Flutter-проверок, история/удаление и сохранение существующего Google/FCM в обеих известных версиях дополнения. Проверены реальные обработчики сайта на локальной копии с отдельными базами и подставными поставщиками: оплаты, заказы, вход, безопасность и уведомления. Живые платежи или удаление настоящих клиентских данных не выполнялись.

В расширенной проверке локальной копии сайта 134 проверки прошли; одна проверка встроенного видео требует отсутствующий в этой копии `static/app/dc-guide.mp4`. Такое же отсутствие есть до обновления. Видео и его обработчики в данном обновлении не изменены.

Подключение SSH из среды разработки недоступно. Установка на вашем сервере, сборка с вашим ключом и проверка нового APK на телефоне выполняются по шагам выше. Архив не является отчётом об уже выполненном развёртывании.
