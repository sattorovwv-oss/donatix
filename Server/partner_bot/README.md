# ⭐ Stars Bot — продажа Telegram Stars и Premium

Telegram-бот на **aiogram 3** с балансовой моделью: пользователь пополняет
баланс переводом на карту (Душанбе, сомони), а покупки списываются с баланса
и выдаются через Fragment автоматически.

## Как устроены деньги

```
Пополнение                     Покупка
─────────────                  ────────────────────────────────
юзер вводит сумму              выбирает количество звёзд
   ↓                              ↓
бот даёт реквизиты             списание с баланса (атомарно)
   ↓                              ↓
юзер шлёт чек                  заказ → Fragment
   ↓                              ↓
админ жмёт «Зачислить»         ├ успех  → выдано
   ↓                              ├ отказ  → деньги вернулись
баланс пополнен                  └ таймаут → деньги придержаны, решает админ
+ реферал получает %
```

Все суммы хранятся **целыми числами в дирамах** (1 сомони = 100 дирам).
Float для денег не используется нигде.

### Почему при таймауте деньги не возвращаются автоматом

Если Fragment не ответил, неизвестно, ушли звёзды или нет. Автовозврат в такой
ситуации означал бы раздачу товара бесплатно. Поэтому заказ уходит в статус
`failed`, деньги придерживаются, а админу приходит уведомление с двумя
командами: `/done <id>` (заказ дошёл) или `/refund <id>` (не дошёл).

## Установка на сервер — одна команда

```bash
bash <(curl -sSL https://raw.githubusercontent.com/alijon26062006-bit/AlijonMahmadjonov/claude/telegram-stars-sales-bot-caqst0/stars_bot/install.sh)
```

Скрипт поставит зависимости, скачает бота, спросит настройки, заведёт
автозапуск через systemd и проверит, что бот поднялся. Работает на
Ubuntu / Debian / CentOS с systemd.

После установки появляется команда **`stars-bot`**:

| Команда | Что делает |
|---|---|
| `sudo stars-bot update` | **обновить код и перезапустить** |
| `sudo stars-bot logs` | смотреть логи живьём (Ctrl+C — выйти) |
| `sudo stars-bot status` | работает ли бот |
| `sudo stars-bot restart` | перезапустить |
| `sudo stars-bot errors` | последние ошибки |
| `sudo stars-bot setup` | пройти всю настройку заново |
| `sudo stars-bot mystars` | подключить MyStars — спросит ключ, адрес, валюту |
| `sudo stars-bot delivery` | выбрать способ выдачи |
| `sudo stars-bot pay` | реквизиты карты |
| `sudo stars-bot prices` | цены |
| `sudo stars-bot telegram` | токен бота и ваш ID |
| `sudo stars-bot backup` | сохранить копию базы |

Цены, реквизиты, рассылка и промокоды меняются прямо в боте через `/panel` —
на сервер для этого заходить не нужно.

Каждая команда настройки спрашивает по одному вопросу за раз и сама
перезапускает бота. Если хочется без вопросов —
`sudo stars-bot mystars ВАШ_КЛЮЧ` применит всё одной строкой.

`update` скачивает свежий установщик из репозитория, поэтому обновление
применяется целиком, даже если изменился сам установщик. `.env` и база с
заказами при обновлении не трогаются.

Бот работает от отдельного пользователя `starsbot`, а не от root, и systemd
ограничивает ему доступ к файловой системе — писать он может только в свою
папку с базой.

Пути меняются переменными: `DIR=/srv/bot bash install.sh`.

## Запуск на своём компьютере

**Windows** — двойной клик по `start.bat`.
**Linux / macOS** — `bash start.sh`.

Скрипт сам создаст окружение, поставит зависимости и при первом запуске
спросит настройки. Больше ничего делать не нужно.

Если хочется вручную:

```bash
cd stars_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python setup.py           # мастер настройки, создаёт .env
python -m app.main
```

`python setup.py` можно запускать сколько угодно раз — он показывает текущие
значения в скобках, Enter оставляет их как есть. Так удобно, например,
переключиться с `mock` на `api`, когда придёт ключ Fragment.

### Что понадобится

| Переменная | Что это | Где взять |
|---|---|---|
| `BOT_TOKEN` | токен бота | [@BotFather](https://t.me/BotFather) → `/mybots` |
| `ADMIN_IDS` | твой Telegram ID | [@userinfobot](https://t.me/userinfobot) |
| `PAY_CARD_NUMBER` | карта для приёма переводов | твои реквизиты |
| `STAR_PRICE_DIRAM` | цена звезды в дирамах (`20` = 0.20 сомони) | твоё решение |

Бот **не запустится**, если не задан админ, карта или цена, — и напишет,
чего именно не хватает. Это защита от ситуации, когда покупатели переводят
деньги в никуда.

> ⚠️ **`.env` в `.gitignore` — ключи и мнемонику не коммить.**
> Мнемоника из 24 слов = полный доступ к TON-кошельку. Если она где-то
> засветилась (чат, скриншот, переписка) — сразу переводи средства на новый
> кошелёк и создавай новый ключ.

## Проверка получателя

Самая дорогая ошибка покупателя — опечатка в юзернейме: звёзды уходят чужому
человеку и вернуть их нельзя. Поэтому перед оплатой бот показывает, **на какой
аккаунт** уйдёт заказ:

```
🔍 Проверьте получателя

👤 Аккаунт: Алиджон Махмаджонов
🔗 Юзернейм: @alijon26

❗️ Это чужой аккаунт. Убедитесь, что не ошиблись в юзернейме.

⚠️ ⭐️ 100 звёзд уйдут именно на этот аккаунт.
   После отправки вернуть их нельзя.

Это верный аккаунт?
[✅ Да, это верный аккаунт]
[✏️ Другой юзернейм]
```

Имя аккаунта приходит от Fragment — то есть подтверждается тем же сервисом,
который будет отправлять звёзды. Если Fragment аккаунт не знает, заказ не
начнётся.

Для покупки себе есть кнопка **«⭐️ Себе»** — юзернейм подставляется из
аккаунта, вводить руками ничего не надо, и опечатка невозможна. Если у
покупателя не установлен юзернейм, бот объясняет, где его включить: Fragment
умеет отправлять только на публичные юзернеймы.

## Админ-панель

Команда **`/panel`** — одна точка входа, дальше всё кнопками. Настройки
меняются прямо в боте и сохраняются в базе: перезапуск и обновление их не
сбрасывают, лезть в `.env` не нужно.

```
🛠 Админ-панель
├ Пользователей · пополнено · продано · на балансах
└ Цена звезды и прибыль с неё

[📣 Рассылка]
[💵 Цены и наценка]  [💳 Реквизиты]
[📥 Заявки]          [📞 Тикеты]
[📦 Заказы]          [🎟 Промокоды]
[📊 Статистика]      [🔀 Разделы]
[💼 Кошелёк]          [🔌 Проверить связь]
[📝 Объявление в поддержке]
[🔗 Рекламные ссылки]
```

### 🔌 Проверить Fragment

Пошагово проверяет, возможна ли выдача: получает токен, читает баланс
кошелька и прямо говорит, что делать:

* **режим mock** — предупреждает, что клиенты получат «заказ выполнен», не
  получив звёзд;
* **связь есть** — можно продавать;
* **связь потеряна** — советует выключить продажу в разделе «Разделы», чтобы
  люди не платили и не получали возврат.

### 📣 Рассылка

1. Выбираете кому: всем · только покупателям · у кого есть баланс · без покупок
2. Присылаете сообщение — **любого типа**: текст, фото, видео, GIF, документ,
   голосовое, кружок, стикер. Форматирование сохраняется.
3. По желанию добавляете кнопки-ссылки, по одной в строке:
   ```
   Наш канал - https://t.me/mychannel
   Купить звёзды | https://t.me/mybot
   ```
4. Предпросмотр — бот присылает сообщение вам, ровно как увидят клиенты
5. Отправка с живым счётчиком: доставлено · заблокировали · ошибки

Рассылка идёт через `copyMessage`, поэтому работает любой тип вложения без
пересборки. При требовании Telegram притормозить бот ждёт и досылает.

### 💵 Цены и наценка

**Автоцены.** Кнопка «⚪️ Включить автоцены» — и бот сам раз в час спрашивает
цену у сервиса, пересчитывает продажную по вашей наценке и держит её
постоянной. Курс TON гуляет в течение дня: без этого наценка расползается —
сегодня 15%, завтра 3%, послезавтра продажа в убыток.

Включается только после успешного пробного обновления, иначе можно решить,
что цены обновляются, а они молча стоят. О скачке больше 20% бот
предупреждает отдельно.

**Разовая проверка.** Кнопка «📡 Узнать себестоимость» спрашивает
цену у сервиса выдачи, переводит её в сомони и предлагает записать:

```
📡 Себестоимость от сервиса выдачи

За 1000 звёзд вы платите 11.50 TON
Это $32.78 (курс TON: $2.85)

💱 По вашему курсу 10.90 с. за доллар:
└ одна звезда обходится в 0.36 с.

📈 С вашей наценкой 10% продавать по 0.40 с. за звезду
   (прибыль 0.04 с. со звезды, 40.00 с. с 1000)
```

Сервис считает в TON и долларах, а вы продаёте за сомони — поэтому один раз
задайте **курс доллара** (кнопка «💱 Курс доллара»). Курс TON бот берёт из
ответа сервиса сам.

Дальше вводите **процент наценки** — панель считает цену продажи и показывает:

```
├ Себестоимость: 0.18 с.
├ Наценка задана: 30%
├ Цена продажи: 0.23 с.
├ Фактическая наценка: 27%
└ Прибыль с 1 звезды: 0.05 с.

💡 С заказа в 1000 звёзд заработок: 50.00 с.
```

Если цена продажи окажется ниже себестоимости, панель прямо напишет, что это
убыток. Там же меняются тарифы Premium, границы заказа, минимальное
пополнение и реферальный процент.

### 📈 Отчёты

`/panel` → **📈 Отчёты**. Периоды: сегодня, вчера, 7 дней, 30 дней, всё время
и **свой диапазон** — присылаете `01.08 15.08` (год можно не писать).

```
📈 Последние 7 дней

💰 Деньги
├ Продано на: 1 250.00 с.
├ Себестоимость: 1 050.00 с.
└ Прибыль: 200.00 с. (19%)

📦 Заказы
├ Выполнено: 42
├ Возвращено: 3 (60.00 с.)
├ На разборе: 0
├ Звёзд продано: 8 400
└ Premium: 12 мес.

👥 Клиенты
├ Новых: 15
├ Покупали: 28
└ Пополнений: 31 (1 400.00 с.)

По дням
20.08 ██████░░░░ 180.00 с.
21.08 ████████░░ 240.00 с.
```

Себестоимость **записывается в заказ в момент покупки**. Курс меняется, и без
этого прибыль за прошлые дни пересчитывалась бы задним числом. У заказов,
сделанных до этого обновления, себестоимости нет — по ним отчёт честно пишет,
что прибыль не посчитать, вместо того чтобы показать выручку как прибыль.

Дни считаются по вашему часовому поясу (по умолчанию UTC+5, Душанбе), иначе
вечерние заказы попадали бы во «вчера».

### 🏙 Оплата в «Душанбе Сити»

Если задан номер счёта, при пополнении появляется зелёная кнопка
**«🏙 Оплатить в Душанбе Сити»**. Она открывает приложение с уже вписанными
счётом и суммой — покупателю не нужно переписывать 16 цифр и сумму вручную,
а значит негде ошибиться.

Ссылка собирается из настроек и выбранной суммы:

```
https://pay.dc.tj/?a=СЧЁТ&c=ПОДПИСЬ КОД&f1=УСЛУГА&s=СУММА
```

| Настройка | Что это |
|---|---|
| `🏙 Счёт «Душанбе Сити»` | параметр `a` из вашей ссылки pay.dc.tj |
| `📝 Подпись в платеже` | что писать перед кодом, например `@uwayscoder` |
| `🔢 Код услуги` | параметр `f1`, обычно `133` |

В комментарий к переводу подставляется **код платежа** вида `TOP2248`. Он же
сохраняется в заявке и показывается в уведомлении админу — по нему перевод
находится в банковской выписке, даже если чек пришёл позже или не пришёл вовсе.

Кнопка «🏙 Проверить кнопку оплаты» в разделе реквизитов собирает пробную
ссылку на 50 сомони: можно убедиться, что приложение открывается и данные
подставились, ничего не оплачивая.

Реквизиты карты показываются в любом случае — кнопка их дополняет, а не
заменяет.

### 💼 Кошелёк

Схема «пополнил один раз — работает само» ломается в одном месте: когда деньги
на кошельке Fragment кончаются, бот продолжает принимать заказы, клиенты платят
и получают возврат, а владелец узнаёт об этом от них.

Поэтому бот следит сам:

* считает выданные звёзды и месяцы Premium с последнего пополнения и
  показывает их себестоимость — видно, когда пора доливать;
* после **3 неудачных выдач подряд** (порог настраивается) выключает продажу
  звёзд и Premium и присылает тревогу с текстом последней ошибки;
* тревога отправляется один раз, а не на каждый следующий заказ;
* кнопка «✅ Я пополнил кошелёк» обнуляет счётчики и включает продажу обратно.

Успешная выдача обнуляет серию неудач, поэтому одиночный сбой сети продажу
не гасит.

### 🎨 Оформление

Каждый значок в боте меняется из панели: `/panel` → **🎨 Оформление**. Значки
разложены по группам (Товары, Деньги, Разделы, Состояния, Навигация), и
изменение видно клиентам **сразу** — перезапуск не нужен.

Тексты не содержат значков напрямую: они пишут токен `[[premium]]`, а
подстановка идёт при обращении. Поэтому смена одного значка меняет его во всех
экранах и кнопках разом.

Есть сброс одного значка и всех сразу.

**Премиум-эмодзи.** Пришлите боту сам премиум-эмодзи — он вытащит его ID
из сообщения, искать ID вручную не нужно. Внутри тега остаётся обычный
значок: его увидят там, где премиум-эмодзи не отображается.

Право на такие эмодзи зависит от подписки владельца бота
([Bot API](https://core.telegram.org/bots/api): их могут использовать боты,
чей владелец имеет Telegram Premium, либо купившие юзернейм на Fragment).
Поэтому они **выключены по умолчанию**: кнопка «💎 Проверить премиум-эмодзи»
отправляет пробное сообщение и включает их только если Telegram принял.

Если подписка кончится, Telegram начнёт отвергать каждое сообщение с
премиум-эмодзи — бот замолчал бы целиком. Этого не произойдёт: мидлварь
`emoji_guard` ловит такой отказ, убирает теги, повторяет отправку обычными
значками и выключает премиум-эмодзи до следующей проверки.

> В тексте кнопки разметка не поддерживается, но премиум-эмодзи ставится
> отдельным полем `icon_custom_emoji_id` — так он виден и на кнопках.

### Цвета кнопок

Bot API 9.4 добавил полю `style` три значения — `primary` (синий),
`success` (зелёный), `danger` (красный). Цвет здесь несёт смысл, а не
украшает:

| Цвет | Где |
|---|---|
| 🟢 `success` | подтвердить, оплатить, зачислить, пополнить, включить |
| 🔵 `primary` | главное действие экрана: купить, отправить рассылку |
| 🔴 `danger` | отменить, отклонить, выключить, сбросить |
| ⚪️ без цвета | навигация и второстепенное |

Навигация намеренно оставлена без цвета: если выделить всё, выделенным не
будет ничего.

Оттуда же `icon_custom_emoji_id` — премиум-эмодзи прямо на кнопке. Ставится,
только если владелец задал его для этого значка и проверка прошла; обычный
значок при этом убирается из текста, чтобы не дублировался.

### 🎨 Премиум-эмодзи

Десять значков главного экрана уже прописаны премиум-эмодзи владельца — ID
лежат в `app/emoji.py`, в словаре `PREMIUM_IDS`. Показываться они начнут
только после проверки: `/panel` → **🎨 Оформление** → **Проверить
премиум-эмодзи**. Бот отправляет пробное сообщение и включает их, лишь
когда Telegram его принял.

Так сделано намеренно: если премиум-эмодзи не положены аккаунту, Telegram
отвергает сообщение целиком — бот бы замолчал весь, а не потерял значок.
На этот же случай есть страховка: при отказе Telegram бот снимает
премиум-значки, повторяет отправку обычными и выключает их сам.

**На кнопках премиум-эмодзи Telegram не показывает** — там всегда виден
запасной обычный значок. Реально они видны в тексте сообщений.

Каждый значок правится в панели: пришлите сам премиум-эмодзи (бот возьмёт
ID) или ID числом. Кнопка **🚫 Убрать премиум-эмодзи** снимает его насовсем,
даже если ID прописан по умолчанию.

### 💱 Курс доллара

Себестоимость на стороне сервиса выдачи — в долларах, продаёте вы за сомони,
поэтому курс задаёт все цены разом. Бот умеет брать его сам.

`/panel` → **💵 Цены и наценка**:

* **💱 Обновить курс сейчас** — спрашивает курс и показывает, откуда он взялся
  и как изменился;
* **🔄 Курс: авто / ✋ Курс: вручную** — обновлять ли курс перед каждым
  пересчётом цен;
* **➕ Надбавка к курсу** — процент поверх биржевого курса.

Источники — бесплатные, **ключ не нужен ни для одного**, спрашиваются по
очереди, пока кто-то не ответит:

| Источник | Ключ | Что отдаёт |
|---|---|---|
| `open.er-api.com` | не нужен | обновление раз в сутки |
| `cdn.jsdelivr.net` (currency-api) | не нужен | обновление раз в сутки |
| `latest.currency-api.pages.dev` | не нужен | зеркало предыдущего |

**Про надбавку.** Источники дают биржевой курс, а доллары в Душанбе вы
покупаете дороже. Надбавка выравнивает разницу: сравните курс из бота с
курсом обменника и поставьте процент. Пока он 0, бот берёт биржевой курс
как есть.

Курс вне диапазона 2–100 сомони за доллар отбрасывается как мусор, и бот
переходит к следующему источнику. Если не ответил никто — остаётся прежний
курс, продажи не останавливаются, а в панели видно, что обновление не прошло.
Ручной ввод курса никуда не делся и всегда главнее.

### ⭐️ Отзывы

Как только заказ выдан, бот сам предлагает покупателю оценить его — пять
кнопок от ⭐️ до ⭐️5 и «Не сейчас». После оценки просит пару слов; можно
отправить и без текста.

**В канал отзыв сразу не идёт.** Он приходит владельцу с двумя кнопками.
Клиенту про модерацию не сообщается — он видит только «Скоро он появится
в нашем канале»: слово «проверка» звучит так, будто отзыв цензурируют.

```
⭐️ Новый отзыв на проверку
━━━━━━━━━━━━━━━━━━━━

├ Оценка: ⭐️⭐️⭐️⭐️⭐️ (5/5)
├ Заказ: №42 — ⭐ 100 звёзд
└ Покупатель: @buyer (777)

Всё пришло за минуту, спасибо!

[✅ Опубликовать]  [🗑 Удалить]
```

**Опубликовать** — отзыв уходит в канал в том же оформлении, что и остальной
бот: оценка звёздами, жирный заголовок, текст в цитате.

```
⭐️⭐️⭐️⭐️⭐️
Отзыв о покупке
━━━━━━━━━━━━━━━━━━━━

Всё пришло за минуту, спасибо!

├ Товар: ⭐ 100 звёзд
└ Покупатель: @buyer
```

**Удалить** — отзыв никуда не публикуется.

Настройки: `/panel` → **⭐️ Отзывы**. Там канал (`@kanal` или числовой ID),
переключатель «спрашивать после заказа», средняя оценка и кнопка, которая
пришлёт всё зависшее на проверке. Бот должен быть в канале администратором
с правом публиковать.

**📣 Спросить у прошлых покупателей.** Те, кто покупал до появления отзывов,
сами ничего не получали. Кнопка находит их в базе и пишет каждому один раз:

* по одному человеку — один заказ, самый свежий выданный;
* кто уже оставил отзыв или кого уже спрашивали — пропускается;
* заблокировавшие бота и забаненные — тоже;
* отменённые заказы не в счёт.

Отметка «спрашивали» ставится на каждого отдельно, поэтому кнопку можно
нажимать хоть каждый день: одних и тех же людей бот не побеспокоит, а новые
в списке появятся сами. Дальше всё как обычно — оценка, текст, ваша
проверка, публикация.

**Один заказ — один отзыв.** Держится на `UNIQUE(order_id)` в базе, а не на
проверке в коде: две кнопки, нажатые подряд, проскочили бы обе. Оценить
можно только свой и только выполненный заказ. Кнопки «Опубликовать» и
«Удалить» работают один раз: повторное нажатие отвечает «уже разобран».

Если Telegram не принял пост (бот не в канале, нет прав), отзыв **остаётся
на проверке** и кнопку можно нажать снова — владелец видит точную причину.

Канал отзывов заодно включает кнопку **Отзывы** в меню клиента, ссылка
берётся из него же.

### 🧿 Округление цен

Точная цена звезды даёт суммы вроде 8.02 или 160.40 — в магазине это
выглядит как недоделка. `/panel` → **💵 Цены и наценка** → **🧿 Округление
цен**, там четыре способа с живым примером на вашей текущей цене:

| Способ | 100 звёзд по 0.1604 |
|---|---|
| без округления | 16.04 с. |
| **вверх до сомони** (по умолчанию) | 17.00 с. |
| до сомони | 16.00 с. |
| вверх до 5 сомони | 20.00 с. |

Округление всегда считается **от точной цены**, а не от уже округлённой —
иначе сумма ползла бы вверх при каждом пересчёте автоцен.

Действует на любой заказ звёзд — и на кнопку-набор, и на введённое вручную
количество, иначе через ручной ввод те же звёзды выходили бы дешевле.
Тарифов Premium не касается: там суммы вы задаёте сами.

Калькулятор и подсказка «на ваш баланс хватит на N звёзд» учитывают
округление и никогда не обещают больше, чем реально можно купить.

### 🕹 Игры — Free Fire, PUBG и другие

Каждая игра — отдельный товар: её можно закрепить за партнёром и увидеть
в отчётах отдельной строкой. `/panel` → **🕹 Игры**.

В меню клиента Steam и игры живут за одной кнопкой **🕹 Игры и Steam** —
для покупателя это одно действие: пополнить игровой аккаунт. Внутри
раздела Steam идёт первым, дальше игры.

1. **➕ Добавить игру** — одной строкой `код название`, например
   `free_fire_br 🔥 Free Fire`. Код — это `category_id` у поставщика;
2. **📦 Проверить пакеты** — бот покажет пакеты с ценой и себестоимостью
   ровно так, как их увидит клиент;
3. **📈 Своя наценка** — процент только для этой игры (`0` — брать общую);
4. **✅ Показать в меню**.

Цена пакета обычно не хранится: себестоимость поставщика в долларах × курс
+ наценка. Меняется курс — меняются все пакеты сразу.

**Цену любого пакета можно поставить руками.** Нажмите **📦 Проверить
пакеты** — каждый пакет станет кнопкой. Внутри видно себестоимость, цену,
прибыль в сомони и процентах, и есть **✏️ Своя цена**:

```
📦 100 алмазов

├ Игра: 🔥 Free Fire
├ Себестоимость: 10.90 с. ($1.00)
├ Цена продажи: 25.00 с. (своя)
├ По наценке было бы: 14.00 с.
└ Прибыль: 14.10 с. (129%)
```

Своя цена **не пересчитывается** при смене курса и наценки — она держится,
пока её не вернуть кнопкой **♻️ Вернуть по наценке**. В списке такие пакеты
помечены ✏️, так что видно, где цена своя, а где расчётная.

**Свой ключ поставщика.** `/panel` → **🕹 Игры** → **🔑 Ключ поставщика
для игр**. Когда игры ведёт второй партнёр, заказы списываются с его счёта,
а не с общего: звёзды и Premium идут с основного ключа, игры — с этого.
Оставьте поле пустым — всё пойдёт с одного счёта.

Так расходы партнёров не смешиваются сами собой, без ручного разбора «кто
кому сколько должен». На экране **💳 Балансы ключей** оба счёта показаны
отдельными строками.

**Ник по ID.** Клиент вводит числовой ID, бот показывает ник, чтобы тот
убедился, что платит себе. Для Free Fire ник берётся с gameskinbo (ключ
в том же разделе), для остальных игр — у самого поставщика.

Ник — не пропуск к покупке. Пополнение идёт по ID, ник нужен для сверки
глазами, поэтому покупку блокирует **только** явный ответ «такого игрока
нет». Если ник просто не пришёл, бот пишет «ID принят» и просит проверить
цифры самостоятельно.

Бесплатный план gameskinbo — 100 запросов **в месяц**, поэтому удачные
ответы держатся в памяти полчаса. Неудачи не кэшируются: сервис мог
просто промолчать.

**Заказ почти всегда уходит «в обработку».** Ответ поставщика `ok:true`
означает, что заказ принят, а не что алмазы у игрока, поэтому:

* бот сохраняет номер заказа у поставщика и проверяет статус сразу после
  создания;
* если заказ ещё в работе — опрашивает его **каждые 3 секунды первые три
  минуты**: выдача обычно занимает секунды, и клиент узнаёт почти сразу;
* дальше заказ подхватывает фоновая задача, которая добирает незавершённые
  каждые 5 минут — без неё заказ завис бы навсегда;
* заказ, висящий дольше **20 минут**, закрывается возвратом денег клиенту,
  а владельцу приходит предупреждение с номером у поставщика: если заказ
  всё-таки прошёл, товар ушёл бесплатно и это надо проверить в кабинете;
* явный отказ (например `INSUFFICIENT_BALANCE`) возвращает деньги сразу
  и пишет владельцу причину — очередь из зависших заказов не копится.

Каждый заказ уходит с уникальным `Idempotency-Key`, поэтому повтор запроса
не спишет у поставщика деньги дважды.

### 🤝 Партнёры

Когда дело ведут вдвоём, а деньги приходят на одну карту, делить надо не
деньги, а учёт. `/panel` → **🤝 Партнёры**.

**За каждым партнёром закрепляются его товары.** Прибыль с товара целиком
идёт владельцу: звёзды и Premium — одному, игры и Steam — другому. Товары
назначаются в карточке партнёра → **📦 Товары партнёра**, нажатием на товар.

```
🤝 Партнёры

💰 Общая прибыль: 60.00 с.
├ Продано на: 370.00 с.
└ Себестоимость: 310.00 с.

👤 Алиджон
├ ⭐ Звёзды: 2 шт. на 300.00 с. · прибыль 50.00 с.
├ Заработал: 50.00 с.
├ Внёс в оборот: 500.00 с.
├ Забрал себе: 200.00 с.
└ На руках: 350.00 с.

👤 Напарник
├ 🎮 Steam: 1 шт. на 70.00 с. · прибыль 10.00 с.
├ Заработал: 10.00 с.
└ На руках: 10.00 с.

📦 Не закреплено
├ 👑 Telegram Premium: 3 шт. на 90.00 с. · прибыль 12.00 с.
└ делится по долям

💳 Пришло на реквизиты
├ Пополнений: 12
└ Всего: 1 450.00 с.
```

Три блока отвечают на три вопроса: **сколько продал каждый**, **что ещё
никому не отдано** и **сколько всего денег пришло на карту**.

Товар без владельца делится по долям (`📊 Доля от нераспределённого`), а
если доли не заданы — показывается как ничей, пока его не закрепят.

**На руках = прибыль его товаров + доля от общего + внесённое − забранное.**
Спорить не о чем: цифры берутся из заказов, а не из чьей-либо памяти.

Сумму взноса можно прислать с примечанием через пробел — `500 пополнил
FazerCards`. Удаление партнёра убирает его из списка, но историю его денег
сохраняет: это записи расчётов.

### 🎮 Пополнение Steam

Третий товар рядом со звёздами и Premium. `/panel` → **🎮 Steam**:

1. **📡 Узнать курс Steam** — спрашивает у сервиса выдачи, во что обходится
   единица кошелька, и сам записывает себестоимость в сомони по курсу
   доллара;
2. **🏷 Цена продажи** — за сколько продаёте 1 единицу (например `0.14` за
   рубль). В разделе сразу видно прибыль с единицы в процентах;
3. **💱 Валюта** и **🔢 Суммы** — что показывать кнопками;
4. **✅ Включить раздел**.

Без цены продажи раздел не включается.

**Логин проверяется до оплаты.** Бот спрашивает сервис, существует ли такой
аккаунт, показывает его имя и только после подтверждения списывает деньги:

```
🔍 Проверьте аккаунт

├ Аккаунт: Mypal Player
├ Логин: mypal
├ Сумма: 500 RUB
├ К списанию: 70.00 с.
└ Останется: 130.00 с.

⚠️ Деньги уйдут на этот аккаунт и вернуть
их будет нельзя. Убедитесь, что логин верный.
```

Если сервис ответил «такого аккаунта нет» — заказ не создаётся, клиент
вводит логин заново. Если сервис **не смог** проверить (не ответил или
вернул невнятное) — заказ тоже не создаётся: со звёздами непроверенный
юзернейм можно продать с предупреждением, а с чужого аккаунта Steam деньги
не вернуть.

Клиенту нужен только **логин входа** — не ник в профиле и не почта. Пароль
и Steam Guard не спрашиваются никогда, и об этом сказано на экране.

### ⭐️ Наборы звёзд

В магазине звёзды продаются кнопками с готовыми количествами — как тарифы
Premium:

```
⭐️ Telegram Stars

💲 Цена: 0.20 с. за звезду

[⭐️ 50 — 10.00 с.]    [⭐️ 100 — 20.00 с.]
[⭐️ 250 — 50.00 с.]   [⭐️ 500 — 100.00 с.]
[⭐️ 1000 — 200.00 с.] [⭐️ 2500 — 500.00 с.]
[✏️ Другое количество]
[‹ Назад]
```

Нажатие сразу ведёт к выбору получателя — количество спрашивать уже не нужно.
Кнопка **✏️ Другое количество** оставляет прежний ввод числом, для тех, кому
нужно ровно 137 звёзд.

**Цены кнопок не хранятся отдельно.** Каждая считается из текущей цены звезды,
поэтому наценку и цену вы правите в одном месте — все кнопки пересчитываются
сами. Тем и отличается от Premium, где у каждого тарифа своя цена.

Список наборов: `/panel` → **💵 Цены и наценка** → **⭐️ Наборы звёзд**.
Присылаете количества через запятую или пробел — `50, 100, 250, 500, 1000, 2500`.
Повторы схлопываются, порядок выравнивается, а числа за пределами лимитов
заказа пропускаются с прямым предупреждением, какие именно.

### 🎟 Промокоды

`/panel` → **🎟 Промокоды** → **➕ Создать промокод**. Бот спрашивает по шагам:

1. **Промокод** — например `ALI10`;
2. **Скидка** — сколько процентов, от 1 до 100;
3. **Количество активаций** — например `100`.

Потом показывает сводку с кнопками **💾 Сохранить** и **❌ Отмена**:

```
🎟 Проверьте промокод

├ Промокод: ALI10
├ Скидка: 10%
└ Лимит активаций: 100
```

После сохранения код сразу активен. В списке видно каждый:

```
🟢 ALI10 — −10%
├ Использован: 3 из 100
├ Осталось: 97
└ Статус: Активен
```

Скидка действует на **все товары** — и звёзды, и Premium.

**Как это видит клиент.** На шаге подтверждения заказа появилась кнопка
**🎟 Промокод**. После ввода стоимость пересчитывается на месте:

```
├ Цена: 20.00 с.
├ Промокод ALI10: −10% (−2.00 с.)
├ К списанию: 18.00 с.
└ Останется: 182.00 с.
```

Кнопка **✖️ Убрать промокод** возвращает полную цену.

**Активация списывается только после выданного заказа.** Если выдача
сорвалась и деньги вернулись — активация не потрачена, клиент может
применить код снова. Пока заказ в работе, его активация зарезервирована,
поэтому код с лимитом 10 не разойдётся на сотню одновременных заказов.
Один клиент использует код один раз.

**Старые промокоды на пополнение баланса** (`/promo КОД сумма лимит`)
работают как раньше — они помечены в списке суммой, а не процентом. Перепутать
их нельзя: код на скидку в профиле не активируется, код на баланс к заказу не
применится, и бот в обоих случаях подсказывает, куда его вводить.

### 🔗 Рекламные ссылки (Deep Links)

`/panel` → **🔗 Рекламные ссылки** → **➕ Создать ссылку**. Присылаете название
площадки — `instagram`, `reklama1`, `partner_1` — и получаете готовый адрес:

```
https://t.me/ВАШ_БОТ?start=instagram
```

Кнопка **📋 Копировать ссылку** кладёт её в буфер обмена одним нажатием.

Как только человек запускает бота по такой ссылке, бот записывает источник в
базу — и больше его не меняет: клиента засчитывает та реклама, что привела его
первой. В карточке ссылки видно:

```
🔗 instagram

https://t.me/moi_stars_bot?start=instagram

📊 Переходы
├ Всего запусков: 3
├ Уникальных людей: 2
└ Новых пользователей: 2

💰 Отдача
├ Покупателей: 1
├ Куплено на: 50.00 с.
└ Из перешедших купили: 50%

📅 Создана 2026-08-26

[📋 Копировать ссылку]
[🗑 Удалить]
```

* **Всего запусков** — сколько раз бот стартовали по этой ссылке, с повторами.
  Telegram сообщает боту не о самом клике по ссылке, а о запуске бота.
* **Уникальных людей** — сколько разных аккаунтов.
* **Новых пользователей** — сколько из них видели бота впервые.
* **Отдача** — сколько этих людей дошли до покупки и на какую сумму: сразу
  видно, какая площадка окупается.

Удаление спрашивает подтверждение и говорит, сколько статистики пропадёт. Сами
клиенты и их заказы остаются на месте, метка источника в карточке клиента тоже.

Чужой `?start=что-угодно` игнорируется: считаются только ссылки, заведённые в
панели. Реферальные ссылки (`?start=ref12345`) работают как раньше и в
рекламную статистику не попадают.

### 👥 Клиенты

`/panel` → **👥 Клиенты**. Присылаете **ID** или **@username** — открывается
карточка с балансом, статистикой заказов и кнопками:

```
👤 @klient
├ ID: 900
├ С нами с 2026-08-26
└ Пришёл: instagram

💰 Финансы
├ Баланс: 65.00 с.
└ Пополнено всего: 50.00 с.

✍️ Правки баланса
├ −10.00 с.
├ +25.00 с. — бонус за отзыв

[➕ Начислить]  [➖ Списать]
[🚫 Заблокировать]
```

Сумму можно прислать с причиной через пробел: `50 бонус за отзыв`. Причина
уходит клиенту в уведомлении и остаётся в истории.

**Списать больше, чем есть, нельзя** — баланс не уводится в минус, иначе
клиент оказался бы должен денег, которых не брал.

Каждая правка записывается: кто, кому, сколько, когда и почему. Она видна
в карточке клиента и отдельной строкой в отчёте — без этого деньги на
балансах не сходились бы с суммой пополнений.

Те же действия остаются командами: `/give`, `/take`, `/user`, `/ban`.

## Fragment

Работает без вашего участия, но требует сид-фразу.

### Почему «accepted» — это ещё не выдача

API асинхронный: `POST /stars` отвечает `{"status": "accepted", "task_id": N}`,
что означает лишь «задача поставлена в очередь». Реальный результат узнаётся
опросом `GET /task/{task_id}`.

Поэтому бот **не считает успешный ответ доставкой** — он опрашивает задачу до
конца и только тогда пишет клиенту «заказ выполнен»:

| Что вернула задача | Что делает бот |
|---|---|
| `completed` / `success` / `done` … | заказ выдан |
| `failed` / `error` / `rejected` … | деньги возвращаются на баланс |
| не завершилась за `TASK_POLL_TIMEOUT` | деньги придерживаются, зовётся админ |
| незнакомый статус | ждёт дальше, пишет статус в лог |

Незнакомый статус никогда не считается успехом: соврать клиенту дороже, чем
позвать админа.

### ⚠️ Про сид-фразу

Шлюзу нужны **24 слова вашего TON-кошелька** (`POST /cookies/login`) — он
входит ими на Fragment и хранит сессию у себя. Технически это даёт владельцам
сервиса полный доступ к кошельку: они могут вывести с него всё.

Защититься от этого кодом нельзя — так устроен сервис. Единственная разумная
мера: **отдельный кошелёк только для бота** с оборотной суммой на пару дней
торговли. Основные деньги держите на другом кошельке, сид которого никуда не
передаётся.

### Имя получателя не проверяется

У шлюза нет метода проверки юзернейма, поэтому имя аккаунта показать
невозможно. Бот говорит об этом покупателю прямо и предлагает открыть
`t.me/username` для сверки — вместо того чтобы делать вид, что аккаунт
подтверждён. Для покупки себе есть кнопка «Себе», где опечатка исключена.

## Чего пока нет

Из макета не реализованы разделы, требующие отдельной инфраструктуры:
**аренда и покупка NFT**, **обычные подарки**, **игры**, **партнёрские боты**.
Каркас к ним готов — добавляются как новые роутеры без переделки ядра.

## Безопасность

- Списание баланса — одним `UPDATE ... WHERE balance >= ?`, поэтому два
  одновременных заказа не уведут баланс в минус (проверено тестом).
- Подтверждение пополнения — условным `UPDATE ... WHERE status = 'pending'`:
  два админа не зачислят одну заявку дважды.
- Промокод: счётчик активаций растёт условием `used_count < max_uses`.
- Держи на кошельке Fragment только оборотный остаток.
- Сверяй сумму и время перевода в банковском приложении, а не только картинку
  чека — это и есть настоящая защита от фейковых скриншотов.
