# Данные для заполнения Play Console — 6 октября 2026

Это инвентаризация кода, не уже отправленная форма и не утверждённая юридическая
политика владельца. Перед отправкой нужно сверить реально включённые провайдеры,
страны, платежи, поддержку и хранение резервных копий на рабочем сервере.

| Данные | Назначение и обработка |
|---|---|
| Email, логин, Google ID, проект | Вход, регистрация и управление аккаунтом; данные Google поступают при Google-входе |
| История покупок, суммы, банковские/криптозаявки | Оформление, сверка платежей и выдача цифровых товаров |
| Фото/PDF чеков | Загрузка выбранного файла; AI-провайдер получает содержимое при включённой AI-проверке |
| ID игрока, Steam-логин, Telegram username | Передаются выбранному поставщику для выполнения заказа |
| Telegram ID и сообщения поддержки | Связь с аккаунтом, боты и поддержка; AI-ответы используют настроенного серверного провайдера |
| IP, User-Agent, история входов, страницы | Безопасность и исходная серверная статистика; не объявлять эти данные анонимными без проверки настройки |
| FCM registration token, случайный device ID | Доставка включённых пользователем уведомлений через Firebase; сервер хранит токен зашифрованным |
| API-ключи и токены подключённых ботов | Только для явно подключённых пользователем интеграций; серверное шифрование |

В мобильном приложении нет Firebase Analytics, рекламного SDK и доступа к
контактам. Камера/галерея/файлы используются для выбранного пользователем чека.
Android runtime notifications permission запрашивается перед включением.
Приложение требует HTTPS; данные авторизации на устройстве хранятся защищённо.
Не отмечайте отсутствие передачи данных третьим лицам: поставщики, Telegram,
Google и включённые AI/платёжные обработчики получают данные выбранных функций.
Классификацию «sharing» / «service provider» в форме определяет владелец по
своим договорам и настройкам, а не автоматически по названию SDK.

Удаление: в приложении «Ещё → Удалить аккаунт и данные» и на
https://donatix.tj/account-deletion после установки новых модулей на сервер. Входы и ключи отзываются сразу; если есть
остаток средств или незавершённая операция, аккаунт ждёт расчёта. Затем worker
удаляет профиль и связанные записи, а постоянная очередь очищает чеки и папки
ботов. Резервные копии и данные внешних провайдеров контролирует владелец.
Юридические сведения владельца, сроки расчёта/удаления и backup retention пока
не предоставлены. Оригинальный текст политики расширен техническими сведениями;
владельцу нужно утвердить его для фактического сервиса.

## Схема платежей

Исходные банковские/криптоплатежи сохранены. Play Billing не добавлен. Выбор платёжной схемы для чужих игровых товаров,
подарочных карт и общего баланса требует проверки фактического каталога и рынков.
FAQ Google отдельно описывает товары, потребляемые только вне приложения,
и подарочные карты. Это может относиться к части каталога Donatix, но является
выводом для проверки, а не гарантией одобрения. D-коины, функции ботов,
премиальные услуги и общая модель пополняемого баланса требуют отдельного
рассмотрения. Правила альтернативной оплаты также зависят от рынков и программ.
Подготовленный workflow AAB не означает разрешение опубликовать такую модель.
AAB в этой сессии не получена.

## Приёмка до публикации

1. Подписанный release APK/AAB, Play App Signing и upload key владельца.
2. Установка на телефон, холодный запуск, фон, выключение уведомлений,
   смена аккаунта, глубокие ссылки, разрешения, файлы, светлая/тёмная тема.
3. Настоящие операции поставщика/платежей с согласованной небольшой суммой,
   выдача, отказ, возврат, повтор запроса и восстановление после потери сети.
4. Скриншоты из принятой сборки и сравнение каждого экрана с исходным сайтом.
5. Data safety, IARC, поддержка, политика, удаление данных, app access.
6. Внутренний/закрытый тест в объёме, который запросит Play Console владельца;
   его требования зависят от типа и даты создания аккаунта.
