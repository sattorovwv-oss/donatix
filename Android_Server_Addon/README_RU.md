# Android: Google-вход и FCM без замены исходников сайта

Это отдельный модуль запуска существующего Donatix. Он не заменяет файлы
`donatix/app.py`, `web.py`, `api.py`, шаблоны или CSS, не меняет схему базы сайта,
не меняет обработку цен, списаний, заказов и выдачи доната. Старую папку
`server_patch` для него устанавливать нельзя.

Модуль использует существующий Google OAuth сайта. Для входа из приложения
добавляется подписанная временная cookie и отдельная страница подтверждения.
Обычный Google-вход без мобильной cookie сохраняет прежний маршрут.
Код администратора из Telegram продолжает проверяться существующим сайтом.
Одноразовый обмен привязан к verifier приложения и действует 10 минут.

Для FCM фоновый обработчик читает новые строки `notifications` приблизительно
раз в секунду через SQLite `mode=ro`. Таблицы устройств, очереди и входов
находятся в **отдельном SQLite-файле**. Ошибки FCM не участвуют в оплате и выдаче.
FCM отправляется после появления существующего события сайта, а не при любом
произвольном изменении строки заказа. Сеть, Android и Firebase могут задерживать
доставку; принудительно остановленное приложение нужно снова открыть.

## Сначала подготовка, затем установка

Живой сервер из этой папки автоматически не изменяется. `stage.py` проверяет
совместимость исходников и текущую команду systemd и создаёт только черновик
drop-in. Неизвестная версия сайта или команда запуска останавливают подготовку.
Не обходите эту проверку заменой хешей: нужно сначала проверить текущую версию.

1. Оставить исходную папку сайта и его `.env` на месте.
2. Скопировать **только** `donatix_android_extension` в отдельный каталог:
   `/opt/donatix-android-addon/v1/donatix_android_extension`.
3. Создать отдельный каталог `/var/lib/donatix-android` с доступом только
   пользователю systemd-сервиса `donatix`. Он будет содержать мобильную базу.
4. Использовать серверный service-account JSON **того же Firebase-проекта**,
   что `GOOGLE_SERVICES_JSON` в Codemagic. Сейчас клиент настроен для
   `donatix-660fc`, Android package `tj.donatix.app`.
   Положить закрытый ключ в `/etc/donatix/firebase-service-account.json`,
   разрешить чтение только пользователю сервиса. Не отправлять ключ в чат,
   GitHub, APK или архив проекта. `google-services.json` не заменяет этот ключ.
5. Запустить подготовку, которая **не перезапускает** сайт:

```bash
python3 stage.py --site /home/donatix/app --service donatix
```

6. Проверить `/tmp/donatix-android-stage/40-donatix-android.conf`.
   Сохраняются пользователь, рабочая папка, host/port и существующий `.env`.
   Если сервису нужен дополнительный `PYTHONPATH`, включить его в черновик.
   Модуль запуска получает `DONATIX_ANDROID_DB`, путь FCM-ключа и Firebase project.
7. До активации сохранить текущую конфигурацию сервиса в закрытый каталог,
   снять согласованную резервную копию SQLite через `backup_db.py` (он использует
   `sqlite3.Connection.backup`, учитывает WAL, проверяет `PRAGMA quick_check`,
   ставит права 0600 и не перезаписывает существующую копию). Не копировать работающий SQLite обычным
   `cp` без учёта WAL. Проверить импорт модуля тем же Python, который запускает сайт.
8. Выбрать короткое окно обслуживания. Установка требует одного перезапуска
   сервиса: краткая недоступность возможна. Положить проверенный drop-in в
   `/etc/systemd/system/donatix.service.d/40-donatix-android.conf`, выполнить
   `systemctl daemon-reload`, затем `systemctl restart donatix`.
9. Проверить статус сервиса, главную, обычный вход, каталог, существующий API
   и `https://donatix.tj/api/v1/android/config`. Ответ должен содержать
   `android_extension_version: 1`, `google_enabled: true`, `fcm_enabled: true`.
   Google будет выключен, если исходные OAuth-ключи сайта не настроены.
10. Если проверка не проходит, выполнить откат ниже сразу.

Зависимости `httpx` и `cryptography` уже используются исходным сайтом
(`cryptography` входит в зависимости web push). Новые версии зависимостей
на рабочем сервере устанавливать автоматически не требуется. Если импорт
не проходит, сначала проверить окружение на копии.

## Откат

Удаляется **только созданный для дополнения drop-in**:

```bash
rm /etc/systemd/system/donatix.service.d/40-donatix-android.conf
systemctl daemon-reload
systemctl restart donatix
systemctl is-active donatix
```

Файлы сайта, его база, `.env`, nginx и сертификаты остаются на месте.
Мобильную базу можно оставить для повторного включения. Не восстанавливайте
старую копию основной базы при обычном откате: это потеряет новые операции клиентов.

## Приложение

Использовать клиент версии 7. В Codemagic ветка `codex/android-existing-api`,
workflow `android-release`. Нужны прежний upload keystore и владелец Firebase.
После установки дополнения в приложении появляется Google-вход. Для push
включить уведомления и разрешить их Android. Проверить реальный заказ,
фон приложения, холодный запуск, выход и смену аккаунта.

Периодическая резервная проверка использует те же реальные ID уведомлений,
что FCM, и не отмечает сообщения сайта прочитанными. Сообщения проверяют
владельца и привязку к текущей сессии. iOS-файлы не менялись.

## Проверки на копии

```bash
PYTHONPATH=/path/to/site:/path/to/Android_Server_Addon python3 -m pytest tests -q
PYTHONPATH=/path/to/site:/path/to/Android_Server_Addon python3 verify_original.py /path/to/site
```

Проверки используют тестовую базу и mock-поставщика. Они не выполняют
реальную оплату, не отправляют FCM и не подключаются к рабочему серверу.
`verification_original` нужен только GitHub CI и не устанавливается на сервер.
Установка и реальная доставка на рабочем сервере пока не подтверждены.
